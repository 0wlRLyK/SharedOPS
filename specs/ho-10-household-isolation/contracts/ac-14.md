# HTTP Contract Notes — AC-14

**Status** Draft

**Scope** HO-93 validation of HO-10 AC-14 only

**Authority** [OpenAPI](../../../docs/api/openapi.yml) · [ADR-0008](../../../docs/adr/0008-rest-api-contract-and-problem-details.md)

| Scenario  | Contract assertion                                                                                                                                                                                                                                                                                              |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S1 and S2 | An authenticated A actor's requests for an existing B resource yield the same contract outcome as inaccessible or absent household resources. The OpenAPI baseline describes planned `404`, stable `NOT_FOUND` and `application/problem+json`. The denial conveys no B payload or identifying resource details. |
| S3        | With equally valid inputs for each operation, compare HTTP status, media type, stable Problem Details content and other response metadata that could disclose existence. Compare according to D2 once approved.                                                                                                 |
| S4        | The permitted B read and valid mutation follow the selected operations' documented success responses. The B read returns the expected resource. Confirm the B mutation's committed effect independently of HTTP.                                                                                                |

OpenAPI declares `GET /api/v1/tasks/{taskId}` planned, with `200` for success and `404` for absence or inaccessibility. It lists no Task mutation. D1 supplies the selected pair, exact operation contracts and availability evidence. D2 supplies the denial comparator, including which request-specific values may vary without disclosing existence. The run needs a valid authenticated session and valid request prerequisites for each input, including CSRF where applicable.

See the [data model](../data-model.md) for the committed-state assertions and the [quickstart](../quickstart.md) for boundary coverage.
