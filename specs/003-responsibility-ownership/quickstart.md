# Validation quickstart

Run in the dedicated feature worktree with JDK 25, Corepack/pnpm and a running Docker daemon. Never run against production or use real account data.

1. Run `make verify`. Confirm Maven Surefire and Failsafe reports execute all new tests without skips, including production Flyway migrations, and formatting/lint succeed. Record the exact revision/tree and environment.
2. In PostgreSQL integration tests create synthetic households A and B, two active A members and a B member. Create an INDIVIDUAL responsibility owned by A1, then verify active/paused current view and archived-only view. Missing, inactive and B owner must be rejected without rows or information leakage. Compare absent and B-owned resource responses and committed state.
3. Transfer A1 to A2 with the current version and a fixed `Clock`; assert owner and exactly one fact with actor/time/old/new owner. Create an existing linked task and verify its `id`, `household_id`, and `responsibility_id` remain unchanged after transfer, archive, restore and rejected operations. For successful operations, use a test-only fail-on-write trigger on `tasks` to detect any attempted insert, update or delete; for rejection, assert the expected error and unchanged committed row. The baseline table has no assignment or status columns, so direct proof of no reassignment or reopening is unavailable in HO-12; HO-18 must add that end-to-end regression when those fields exist. Inject fact write failure through the real transactional boundary; confirm neither owner nor fact commits.
4. Run controlled independent-transaction races: two commands against the same version, and create/transfer/restore against membership deactivation. Check a single winning version, no stale facts, active-owner invariant and committed records. No sleep-based ordering.
5. Archive with A1 historical owner, make that membership inactive in an isolated fixture, and test restore without, with invalid, and with active A2 replacement. Confirm rejected or stale restore remains archived; successful restore is ACTIVE, performs no task write and preserves existing linked task rows. This fixture does not prove the HO-85 deletion journey.
6. Run Flyway upgrade coverage from V8 on an empty schema and on a schema with a V1 placeholder and linked task. Assert the empty upgrade succeeds with constraints, and populated upgrade fails transactionally retaining original rows and schema. Verify invalid direct SQL and owner deactivation are rejected while archived historical owners remain possible.

See [contract](contracts/responsibilities.md) and [data model](data-model.md) for expected request and storage semantics; capture AC-to-test evidence against the final tested tree.
