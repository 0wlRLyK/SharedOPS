# Tasks: One-off tasks and assignment defaults

**Input**: `specs/005-one-off-tasks/spec.md`, `plan.md`, `research.md`, `data-model.md`, `contracts/`, `quickstart.md`; approved owner decisions and `checklists/task-requirements.md`.

**Execution**: Batch implementation uses isolated worktrees and provisional integration. Each task includes its behavior and regression tests. Workers do not execute tests, hooks, whole-feature implementation, or change this task list; the orchestrator executes selected checks and reviews the integrated candidate. `[P]` is advisory; the DAG and scopes below determine readiness.

No project initialization or dependency change is required; the existing pinned Java, Maven, PostgreSQL and test infrastructure is used.

## Phase 3: User Story 1 — Create standalone tasks (P1, MVP)

**Goal**: An active member creates and retrieves standalone tasks. **Independent test**: create title-only and valid optional variants, including either member; reject invalid, inactive and foreign values with no committed row.

- [x] T006 [US1] Implement standalone creation and scoped read using the task port and locked household view in `backend/src/main/java/dev/sharedops/task/application/TaskService.java` and related command/projection types, with `backend/src/test/java/dev/sharedops/task/application/StandaloneTaskIT.java`: title-only yields OPEN, NONE, NORMAL, unassigned, version 0; explicit active partner works; invalid title/options, inactive/foreign assignee and unauthorized direct calls leave committed state unchanged and disclose no foreign data.

## Phase 4: User Story 2 — Create in a responsibility (P1)

**Goal**: Resolve and persist the current owner or explicit selection at creation. **Independent test**: create default, explicit member and explicit unassigned tasks; transfer owner and check old and new records; reject inaccessible and inactive contexts.

- [x] T007 [US2] Extend `backend/src/main/java/dev/sharedops/task/application/TaskService.java` and its commands for linked creation with `backend/src/test/java/dev/sharedops/task/application/LinkedTaskIT.java`: distinguish omitted assignee, explicit null and explicit account; lock household then responsibility, require ACTIVE INDIVIDUAL and active same-household assignee, snapshot owner; reject paused/archived/foreign/missing responsibility and inactive/foreign assignee with no row; verify transfer leaves existing assignment unchanged and later default uses new owner.

## Phase 5: User Story 3 — Edit details and derive overdue (P2)

**Goal**: Version-protected open-task edit and deadline projection. **Independent test**: edit and clear each field, reject stale/invalid/terminal edits with no fact, and evaluate exact D01 boundaries at controlled times.

- [x] T008 [US3] Extend `backend/src/main/java/dev/sharedops/task/application/TaskService.java` and command/projection types for partial edit and derived overdue with `backend/src/test/java/dev/sharedops/task/application/TaskEditAndDeadlineIT.java`: omitted fields unchanged; null clears description/assignee, NONE clears deadline; reject null title/priority, invalid dates/zones, DST gaps and unresolved overlap; enforce active same-household assignment, terminal read-only and stale version conflict; successful edit increments once even for equal values and atomically records actor/time/changed field names, while failures commit neither task changes nor facts; DATE next-local-day and DATE_TIME strictly-after boundaries, NONE and terminal false, precise nanosecond round-trip and host-zone independence use injected clock.
- [x] T009 [P] [US3] Add coordinated PostgreSQL contention coverage in `backend/src/test/java/dev/sharedops/task/application/TaskConcurrencyIT.java` for concurrent versioned edits (exactly one winner and one fact), linked creation versus owner transfer/pause, and membership deactivation, deletion and key-changing updates in both lock orders; assert serialized valid outcome, no invalid committed snapshot or partial writes and bounded completion (PLAN-LOCK-TEST).
