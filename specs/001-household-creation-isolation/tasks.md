## Shared application interface contract

T001 defines these public Java types under `backend/src/main/java/dev/sharedops/household/application/` (one top-level type per file), with adapters constructor-injected. `UUID` means `java.util.UUID` and `Optional` means `java.util.Optional`. Ports are internal to the household module, not named module exports; domain and application values carry no web or persistence annotations.

```java
public interface CurrentAccount {
    Optional<UUID> authenticatedAccountId();
}
public interface HouseholdStore {
    HouseholdSnapshot insert(HouseholdDraft draft);
    Optional<HouseholdSnapshot> findById(UUID householdId);
}
public interface MembershipStore {
    Optional<UUID> findActiveHouseholdId(UUID accountId);
    boolean isActiveMember(UUID accountId, UUID householdId);
    void insertActive(UUID accountId, UUID householdId);
}
public record HouseholdDraft(String name, String icon, String currency, String timezone) {}
public record HouseholdSnapshot(UUID id, String name, String icon, String currency, String timezone) {}
public class CreateHouseholdService {
    public HouseholdSnapshot create(HouseholdDraft command);
}
public class GetHouseholdService {
    public HouseholdSnapshot get(UUID householdId);
}
```

`CurrentAccount` resolves the actual authenticated account from the server security context on each invocation. Missing, anonymous, unauthenticated or unexpected principal yields empty, not a caller-controlled identity; background/system access requires a separate approved policy. The public services accept neither caller-provided account ID nor a household claim as authorization. Missing identity fails closed before persistence. Internal ports receive the resolved actor UUID explicitly per invocation; singleton services and adapters store no actor state. `HouseholdDraft` is the creation command and `HouseholdSnapshot` the result. Domain identities remain framework-independent.

`CreateHouseholdService.create` is externally invoked through the real Spring transaction proxy; it resolves the actor, validates and checks membership before writes, then inserts and flushes household and membership in the same transaction. Existing membership yields an application conflict; validation failures yield validation errors; unrelated persistence errors propagate and roll back. The named active-membership unique-index violation may arise at flush or commit; a nontransactional outer adapter or advice maps only that failure after rollback to `ACTIVE_HOUSEHOLD_EXISTS`. Never catch and continue a rollback-only transaction. `GetHouseholdService.get` resolves identity, then active membership, compares the requested household before loading it, and returns a snapshot only for accessible targets. Missing/inactive/foreign membership, absent or foreign target produce one not-found outcome without reading foreign data or side effects.

Replace the existing named `household::lookup` interface method `boolean existsById(HouseholdId id)` with **only** `boolean isAccessible(HouseholdId id)`, preserving the named interface and propagated `HouseholdId`, but intentionally breaking source/binary and semantic compatibility. Its actual bean is an application boundary using `CurrentAccount` and `MembershipStore.isActiveMember`; null, no/anonymous/unauthenticated or unexpected principal, inactive/missing membership and foreign/absent ID return false without target details. No identity or null target is resolved to a persistence query; with authenticated identity, query only matching active membership, whose FK establishes household existence, never global existence. Remove the raw persistence adapter export and any old overload, search all in-tree consumers and update `backend/src/main/java/dev/sharedops/task/package-info.java` and architecture assertions if needed; if additional consumers require changes outside the listed scope, return them to the orchestrator before editing. Unknown external consumers require explicit migration from `existsById` to `isAccessible`, compatibility documentation and separate downstream identification before integration/deployment. No privileged bypass is invented.
