# Implementation Plan: One-off task time and current context

**Branch**: `feat/HO-81-one-off-task-date-and-timezone-semantics` | **Date**: 2026-11-25 | **Spec**: [spec.md](spec.md)

**Input**: Owner-approved specification, HO-81, D01, FR-HH-07, FR-TASK-03, FR-TASK-11 and NFR-03. The user-supplied [auth/me spec](../auth-me/spec.md) and [T001](../auth-me/tasks.md) are source inputs; preserve those files and include them in the feature handoff so these links remain usable.

## Summary

Implement framework-independent deadline values and derived calendar/overdue operations in the task domain; use `java.time.Clock` injected at the use boundary. Add authenticated current-context read in the household module through an application service and a scoped read port with one account/active-membership/household query, and expose its response in the existing auth API and authoritative OpenAPI. The two slices are independent except for sharing the existing household timezone semantics. This adds no task endpoint, recurrence feature, database migration, or new dependency.

## Technical Context

**Language/Version**: Eclipse Temurin Java 25, no preview. **Primary Dependencies**: existing Spring Boot, Spring Security, Spring Modulith, JDBC, JUnit and Testcontainers. **Storage**: existing PostgreSQL schema and production Flyway migrations; read-only `auth/me` query, no task persistence changes. **Testing**: deterministic JUnit domain tests and application plus real PostgreSQL/HTTP integration and OpenAPI tests. **Target Platform**: existing backend service. **Constraints**: preserve module boundaries, no secrets or real data in evidence; no host/default timezone; no recurrence endpoints, templates or jobs. **Performance/scale**: no new numeric target; bounded current-account lookup only. **Compatibility**: additive authenticated GET; current endpoints and schemas unchanged; no migration. Document source-level domain interface as internal and retain HO-18/HO-016 ownership of future task integration.

## Design and decomposition

1. Define immutable `Deadline` variants and factories, strict local-time resolution, representable next-day boundary and household IANA zone validation. Make invalid combinations impossible. Implement `calendarDate(String)` and `isOverdue(TaskStatus, Instant)` per contract. A `DeadlineEvaluator` application service receives an injected `Clock` and passes its `instant()` to the domain, as ADR-0007 requires. `DATE` stores its validated household zone; date-time local date is derived from the supplied current household zone. Reject gaps and require explicit occurrence for overlaps; no `+24h` boundary arithmetic.
2. Add current-context application port and read service using the server-derived account identity. Fetch current stored account email and optional household in one SQL statement whose active membership join is scoped to that ID. No read of a foreign household by client input. Define a controlled missing-account path, with no leaked data, and test it. Do not return cached principal email as current stored data.
3. Extend `AccountController` with GET response and no-store behavior including requests rejected before controller by security; retain existing `401` Problem Details. Add authoritative OpenAPI request/response/error/header contract. Document additive compatibility and lack of migration. Tests exercise actual JSON including null icon and null household.
4. Update existing `docs/adr/0007-time-source-and-domain-time-handling.md` delivery status with D01’s concrete domain interpretation and interfaces; avoid claiming recurrence was delivered. The two input drafts remain available as source material and must be retained in final scoped artifacts or replaced by durable references with owner approval.
5. Produce tasks that bind behavior and regression tests together, order shared interfaces before their consumers, and separate disjoint task-domain and household scopes. Follow orchestrator batch protocol: workers write tests with behavior, execution and independent review occur on final integrated candidate. The exact planned test names/inputs are in the contract documents; task design maps every FR and scenario to a concrete target.

Review these failure classes in addition to the basic happy paths: (1) a JVM default timezone change must not alter a calculated instant; `DeadlineTest` compares results with restored defaults; (2) a nonexistent midnight in a valid zone uses the next valid start rather than `+24h`; `DeadlineTest` exercises a known midnight gap; (3) two offsets for the same local time yield distinct instants, and missing choice is rejected; `DeadlineTest` asserts both; (4) inactive membership and a foreign household never appear, including when a separate active row exists for another actor; `CurrentContextIT` asserts returned projection and committed database state; (5) a rejected session never leaks account data or loses no-store; `CurrentContextHttpIT` asserts 401 body and header.
